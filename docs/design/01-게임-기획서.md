# 초등 1학년 수학 서바이버 게임 기획서

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 뱀파이어 서바이버류(탑다운 자동전투 생존) + 학습 콘텐츠 |
| 타겟 | 초등학교 1학년 (만 7~8세, 한글 읽기 미숙) |
| 대상 교육과정 | 2022 개정 교육과정 수학 1-1, 1-2 전 단원 |
| 플랫폼 | 웹 브라우저 (설치 없이 바로 실행) |
| 엔진 | Phaser 3 |
| 그래픽 | 실제 도트(픽셀) 그래픽, 무료 에셋(Kenney.nl 등) 활용 |
| 진행 저장 | 브라우저 localStorage 자동 저장 (로그인 없음) |

### 목표
- 아이가 **읽기 능력에 의존하지 않고** 숫자·기호·그림만으로 수학 문제를 풀 수 있게 한다.
- 전투 자체는 쉽고 자동으로 진행되어, 아이가 부담 없이 "다음 문제"를 기대하게 만든다.
- 오답에 페널티를 주지 않아 실패에 대한 두려움 없이 반복 학습하도록 한다.

---

## 2. 핵심 게임플레이 루프

```
[허브(나의 작은 방)]
    ↓ 스테이지(단원) 선택
[스테이지 입장]
    ↓
[이동(자동공격)으로 몰려오는 적 생존] ──┐
    ↓ 경험치 획득                        │ 반복
[레벨업 → 문제 팝업 → 답 선택]           │
    ↓ 정답: 강한 업그레이드              │
    ↓ 오답: 약한 업그레이드(페널티 없음) │
    └───────────────────────────────────┘
    ↓ 제한 시간/웨이브 종료 (목표 4~5분)
[클리어 결과 화면: 재화 획득, 정답률 표시]
    ↓
[허브로 복귀 → 재화로 꾸미기 구매]
```

### 조작
- 이동: 방향키 / WASD (둘 다 지원)
- 공격: 자동(조작 불필요)
- 문제 팝업이 뜨면 게임은 일시정지되고, 마우스/터치로 보기 중 하나를 클릭

---

## 3. 전투 시스템

- 플레이어는 자동으로 가장 가까운 적을 공격한다 (초기 무기 1종 고정).
- 적은 시간이 지날수록 수가 늘고 종류가 다양해진다 (단원별로 난이도 곡선은 동일한 틀 사용, 비주얼만 다르게).
- 플레이어가 일정 경험치를 모으면 **레벨업 → 문제 팝업**이 뜬다.
- 문제 팝업에는 2~3개의 보기가 있고, 각 보기는 "정답이면 강한 업그레이드, 오답이면 약한 업그레이드"로 연결된다. 즉 무엇을 골라도 무언가는 얻는다.
- HP 개념은 존재하되(적과 접촉 시 소량 감소), 게임오버보다는 "잠깐 스쳐도 크게 위협적이지 않은" 수준으로 설계하여 좌절감을 최소화한다. 스테이지 실패(전멸) 시에도 페널티 없이 바로 재도전 가능.

---

## 4. 스테이지 구조 (단원별 스테이지 선택)

- 1학년 1·2학기 전 단원을 각각 **하나의 스테이지(맵)** 로 구성. 총 11개 스테이지.
- 허브의 "꿈 지도"에 해당하는 **단원 지도** 화면에서 스테이지를 선택.
- 목표 클리어 시간: 스테이지당 **4~5분**.
- 스테이지별 상세 문제 설계는 [`02-단원별-문제설계.md`](02-단원별-문제설계.md) 참고.
- 스테이지는 처음엔 1학기 1단원만 열려 있고, 순서대로 클리어하면 다음 단원이 열리는 **순차 잠금 해제** 방식을 기본으로 한다 (부모/교사가 진도에 맞춰 노출시키고 싶어했던 요구 반영).

## 5. 문제(퀴즈) 시스템

### 5.1 표현 원칙
- 텍스트 최소화. 문제는 **숫자, 기호(+, -, =, <, >), 도형, 그림(이모지/아이콘)** 중심으로 표현한다.
- 안내 문구가 꼭 필요한 경우에도 한 줄 이내의 짧은 한글로 보조.

### 5.2 문제 생성 방식
- 단원별로 **문제 템플릿**을 정의하고, 스테이지 진행 중 매 레벨업마다 해당 단원 템플릿에서 파라미터를 무작위로 뽑아 문제를 절차적으로 생성한다.
- 예: `9까지의 수` 단원 템플릿 `count_objects` → 그림 개수를 1~9 사이 무작위로 배치 → 보기 3개(정답 1 + 오답 2, 오답은 정답과 ±1~2 차이) 생성.
- 데이터 스키마 예시:

```json
{
  "unit": "addition_within_9",
  "type": "equation_choice",
  "generate": { "a": [1, 8], "b": [1, 8], "maxSum": 9 },
  "display": "picture+equation",
  "choiceCount": 3
}
```

### 5.3 오답 처리
- 오답 선택 시 정답을 짧게 시각적으로 보여준 뒤(예: 정답 보기에 별 표시), **약한 업그레이드**를 지급하고 바로 게임을 이어간다.
- HP 감소, 게임오버 등 부정적 페널티는 없음.

### 5.4 난이도 곡선
- 같은 단원 안에서도 스테이지 진행(초반→후반)에 따라 숫자 범위/자릿수를 점진적으로 늘린다.
- 예: `100까지의 수` 스테이지 초반엔 두 자리 수 읽기, 후반엔 두 자리 수 비교로 전환.

## 6. 허브 ("나의 작은 방")

레퍼런스 이미지의 다크 코지 톤 + 둥근 카드 UI를 참고하여 구성.

### 화면 구성
- 캐릭터가 있는 작은 방 (도트 그래픽)
- 상단: 보유 재화(가칭 "별조각") 표시
- 버튼: **단원 지도**(스테이지 선택), **꾸미기 방**(코스메틱 상점/착용)
- 하단: 오늘의 추천 단원 안내 (선택 사항, 부모/교사가 지정 가능하도록 추후 확장 여지)

### 재화 & 보상
- 이름(가칭): **별조각**
- 획득처: 스테이지 클리어 시 정답률에 비례해 지급
- 사용처: **꾸미기 요소(외형)만** — 캐릭터 모자/옷/펫 등 코스메틱. 전투력·난이도에는 영향 없음.
- 이유: 학습 실력과 무관하게 공정한 보상을 주되, "내가 모은 것"이라는 동기 부여는 유지.

## 7. 진행 저장 (localStorage)

로그인 없이 브라우저에 자동 저장. 스키마 예시:

```json
{
  "currency": 0,
  "unlockedStages": ["nums_within_9"],
  "stageProgress": {
    "nums_within_9": { "cleared": true, "bestAccuracy": 0.8, "attempts": 3 }
  },
  "ownedCosmetics": [],
  "equippedCosmetics": {}
}
```

## 8. 아트 방향

- 실제 도트(픽셀) 그래픽, Kenney.nl 등 **상업적 사용 가능한 무료 픽셀 에셋 팩**을 다운로드해 조합.
- 허브: 다크 코지 톤(짙은 남색/우드 톤), 둥근 카드형 UI, 부드러운 폰트.
- 전투 화면: 밝고 명확한 대비로 적/보기/캐릭터를 쉽게 구분.
- 문제 보기(업그레이드 카드)는 항상 같은 위치·형태를 유지해 아이가 UI 패턴을 빠르게 익히도록 한다.

---

## 9. 기술 스택 & 구조 (초안)

- **엔진**: Phaser 3 (Arcade Physics)
- **언어**: JavaScript (또는 TypeScript, 추후 결정)
- **씬 구성**: `Boot` → `Preload` → `Hub` → `StageSelect`(허브에 통합 가능) → `Stage`(전투) → `Result` → 다시 `Hub`
- **데이터 분리**: 커리큘럼/문제 템플릿은 별도 JSON으로 관리하여, 게임 로직 코드를 건드리지 않고 문제 내용만 추가/수정 가능하게 한다.

## 10. 범위 밖 (이번 설계에 포함하지 않음)

- 로그인/서버/멀티 디바이스 동기화
- 스탯형 영구 강화(재화는 코스메틱 전용)
- 음성(TTS) 안내 — 추후 확장 고려 가능하나 1차 범위 제외
- 부모/교사용 대시보드 — 추후 확장 고려

---

## 11. 테스트 방침

- 문제 생성 로직(정답 계산, 오답 후보 생성)은 **순수 함수**로 분리하여 자동 테스트로 정답 정확성을 검증한다.
- 실제 재미/난이도/조작감은 자동화가 불가능하므로, 대상 연령대 아이와의 **실플레이 테스트**로 확인한다.
